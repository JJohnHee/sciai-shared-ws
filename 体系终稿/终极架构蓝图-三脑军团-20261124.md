## 三、联通层（SSH → Git/GitHub 为主线）

```
当前问题：SSH 功效低 + Tailscale 中继断联风险

解决方案（三层联通）：
┌────────────────────────────────────┐
│ 层 1：Git/GitHub（主线，不怕断联）    │
│ ├─ 共享仓 sciai-shared-ws           │
│ ├─ 节点定时 git pull 拉任务          │
│ ├─ 节点执行后 git push 交结果         │
│ └─ 断联恢复后自动同步                 │
├────────────────────────────────────┤
│ 层 2：Tailscale（低延迟实时通道）     │
│ └─ 用于需要实时响应的场景             │
├────────────────────────────────────┤
│ 层 3：Cloudflare/openp2p（兜底）     │
│ └─ Tailscale 断时的备选              │
└────────────────────────────────────┘

Git 通信协议：
节点 → git pull → 执行任务 → git commit + push → 蜂王 git pull 验收
优势：断联不怕（恢复后 git pull 补上）+ 有版本历史 + 有 diff 审计
```

## 六、节点持续进化

```
进化闭环：
1. 节点执行任务 → 产物落盘 → git push
2. 蜂王验收 → 评价（好/坏/改进点）
3. 评价写入节点分记忆（memory/feedback.md）
4. 节点下次执行时读自己的记忆 → 避免重复错误
5. 重要经验合并到 shared-memory → 其他节点也能学

结果：越用越聪明，不需要人工干预每个节点的改进
```
